## 1. 洛神 AI 当前公开定位

洛神 AI 公开定位为 **AI 短剧 · 漫剧 · 宣传视频一站式创作平台**，强调从剧本到成片、从单集到系列的完整创作链路。

公开核心能力包括：

- AI 剧本与叙事引擎；
- AI 智能创作 / 手动创建 / 导入剧本；
- 大纲与分集拆分；
- 新手 / 专业双模式；
- 一站式短剧 Workflow；
- 三重关键帧连贯性控制；
- 文博文化语料库；
- 短剧 / 漫剧、短剧带货、企业 / 文旅 / 政务宣传视频。

## 2. 不要把面试回答做成“谁比谁强”

DramaFlow 是面试 Demo / 二开项目，洛神 AI 是真实商业产品，两者成熟度不在同一层级。

正确的竞品讨论方式是：

> 我通过自己的 Demo 验证了一些相同问题，因此能更具体地理解洛神 AI 为什么要做一站式 Workflow、关键帧一致性、双模式和行业语料库，同时也能提出下一阶段产品假设。

不要说：

> “我的产品比洛神 AI 更好。”

## 4. 我认为洛神 AI 做对的四个产品判断

### 4.1 从“单模型”升级成“完整工作流”

AI 视频产品最容易陷入模型能力展示：输入一句话 → 出一个视频。

但真实短剧生产包含剧本、角色、场景、分镜、视频、配音、剪辑和项目管理。

所以“一站式”并不只是功能更多，而是减少用户在多个工具之间切换造成的上下文损耗。

### 4.2 新手 / 专业双模式

这是非常合理的复杂度管理方式。

新手用户真正关心：

```text
我想表达什么 → 快速得到结果
```

专业用户关心：

```text
用哪个模型
Prompt 是什么
Reference 是什么
镜头参数是什么
为什么这一帧不一致
```

如果把所有参数同时暴露给所有用户，产品会非常难上手。

### 4.3 把一致性放在核心卖点

生成式视频真正进入“生产”后，最大问题往往从“能不能生成”变成：

> 能不能稳定生成连续可用的镜头？

因此角色、场景、关键帧和镜头连贯性的控制，比单纯继续增加模型数量更有业务价值。

### 4.4 行业语料库

文旅 / 文博内容不是纯审美生成。

还涉及：

- 历史事实；
- 地名；
- 人物；
- 文物；
- 品牌规范；
- 机构口径。

如果只依赖通用 LLM，容易产生事实错误和表达偏差。

因此把行业知识库放进创作链路，本质上是在解决 **生成内容的业务可信度**。

## 5. 如果我加入洛神 AI，我会优先验证的产品问题

面试时建议不要一上来讲“大改版”，而是说“我会先验证”。

### 假设 A：新手真正的流失点在哪里？

漏斗：

```text
一句话创意
→ 大纲
→ 剧本
→ 角色
→ Storyboard
→ First Video
→ 完整成片
→ 导出
```

需要看各阶段 conversion 和 duration，找到最大摩擦点。

### 假设 B：一致性问题到底主要来自哪里？

拆成：

- 脸部一致性；
- 服装一致性；
- 场景一致性；
- 镜头空间连续性；
- 动作连续性；
- Prompt adherence。

不能只用一个总的“满意度”。

### 假设 C：用户真正愿意为什么付费？

不是简单问用户“想要什么模型”。

可以测试：

- 更快；
- 更稳定；
- 更一致；
- 更高清；
- 更低成本；
- 更强行业知识；
- 批量生产；
- 商用版权 / 授权保障。

### 假设 D：文旅场景的核心价值是否是“生成”本身？

可能真正价值是：

```text
景区资料 / IP
→ 可控故事模板
→ 批量内容生产
→ 多平台分发
→ 数据反馈
→ 再生产
```

这样产品就从“AI 视频工具”变成“内容供给系统”。

## 6. DramaFlow 可以向洛神 AI 学什么

### Beginner Mode

DramaFlow 当前 Demo 偏工作台和专业创作，应进一步降低首个结果的操作成本。

建议：

```text
一句话
+ 风格
+ 时长
+ 画幅
→ 自动完成默认模型路由
```

专业设置折叠到 Advanced。

### Consistency Layer

现有角色资产继续向：

```text
Character Asset
+ Key Frame
+ Previous Shot
+ Automatic Consistency Check
```

演进。

### Industry Knowledge

新增：

```text
Upload Documents
→ Retrieval
→ Story Generation
→ Citation / Fact Check
```

尤其适合企业、文旅、政务等场景。

## 7. DramaFlow 可以提供的不同观察角度

这不是说 DramaFlow 当前能力超过洛神，而是用于体现产品思考。

### 7.1 Shot-level production unit

把 Shot 当成可独立修改 / 生成 / Retry / 统计成本的最小单元。

这样可以支持：

- 局部返工；
- Shot 成本；
- Shot 质量评分；
- Shot 版本历史；
- 自动找出高失败镜头类型。

### 7.2 Provider abstraction

把模型层抽象出来后，可以做：

```text
极速模式 → 低成本模型
均衡模式 → 主力模型
精品模式 → 高质量模型
失败 → fallback provider
```

最终让用户选择“结果策略”，而不是理解几十个模型名字。

### 7.3 Project observability

面向专业用户，可以提供项目生产数据：

- 哪一步最慢；
- 哪种模型失败率最高；
- 哪类镜头 Regenerate 最多；
- 当前预算消耗；
- 哪个 Shot 卡住交付。

这会让产品从创作工具进一步向 Production OS 演进。

## 8. 面试中可主动问洛神 AI 的问题

以下问题比直接问“你们现在用什么模型”更像产品经理：

### 用户

> 目前洛神 AI 的主要用户更偏专业短剧团队，还是文旅 / 企业这种 B 端客户？不同用户现在是否共用同一套 Workflow？

### 指标

> 团队现在判断一条 AI 短剧生成质量时，内部最重视的是完成率、生成成功率、一致性，还是最终用户导出率？

### 一致性

> 三重关键帧现在主要是给专业用户主动配置，还是系统会根据剧情自动推荐策略？

### 模型

> 模型更新很快，团队现在更倾向让用户感知具体模型，还是逐渐抽象成效果 / 成本 / 速度档位？

### 文旅

> 文博文化语料库目前更多用于剧本阶段，还是已经参与角色、场景和视觉提示词生成？

### 产品路线

> 洛神 AI 下一阶段更希望提升“单条作品质量”，还是“规模化内容产能”？这两个方向在产品设计上优先级会很不一样。

## 9. 面试时的核心态度

推荐保持这个立场：

> 我不是因为做了一个类似 Demo 就认为自己已经知道答案。相反，正因为实际跑过剧本、分镜、生图、视频和任务链路，我更清楚 AI 视频产品里很多问题不能只靠模型升级解决。我希望把这些实际踩过的问题带到更真实的用户、数据和商业场景里继续验证。

这比单纯强调“我会很多 AI 工具”更有说服力。
